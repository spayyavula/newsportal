How do exhibits / charts get authored?

McKinsey-style articles lead with charts. Three workflows differ a lot in implementation cost and editorial flexibility.

A. Image upload (PNG / SVG)

Journalist makes the chart in their preferred tool (Excel, Datawrapper, Figma), exports an image, uploads to Strapi. New editorial.exhibit block: image + caption + source note + figure number. Simplest schema. No chart code. Charts are not interactive, do not respond to dark mode, and can't be regenerated when data updates.

B. Structured chart config in Strapi

editorial.chart block stores chart type (line / bar / area), JSON data series, axis labels, and source note. Rendered on the page via a chart library (Recharts or Observable Plot). Charts respect site typography, dark mode, and screen-reader accessibility. Schema is much heavier; authoring requires structured data entry (or a CSV upload + parser).

C. Hybrid — image exhibits + structured key-stat blocks

Charts stay as uploaded images (simple). But add a separate editorial.key-stat block: a single big number + one-sentence explanation + source. The data-spine feel comes from key-stat callouts breaking up the prose, while exhibits are still images. Lower implementation cost than B; richer than A.
